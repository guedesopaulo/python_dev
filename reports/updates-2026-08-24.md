# Weekly Updates Report — 2026-08-24

## Summary

- **2 security-relevant updates** require prompt attention: `fastmcp 3.4.7` fixes a JWT audience
  validation bypass, and `pydantic-settings 2.15.0` patches a symlink-escape vulnerability in
  `NestedSecretsSettingsSource`.
- **`ruff` 0.16.x is a breaking upgrade**: the default rule-set expanded from 59 to 413 rules;
  running it without adjusting `ruff.toml` will surface many new violations.
- **MCP 2.0 stateless protocol** (released 2026-07-28) is now stable; the `fastmcp` package
  will eventually align with it — worth monitoring before a major version bump lands.
- **`pydantic-settings 2.15.0`** introduces a behavioral change in case-insensitive matching that
  could silently affect config loading; test before upgrading.
- All other outdated packages (`fastapi`, `uvicorn`, `mypy`, `coverage`, `pre-commit`) contain
  only bug fixes and minor improvements with no breaking changes.

## New Community Practices

- **MCP 2.0 stateless protocol (2026-07-28):** The MCP Python SDK reached v2.0 with full support
  for the new stateless protocol revision. Sessions are no longer required; clients auto-negotiate
  the protocol version. FastMCP still runs on the v1 transport layer — once FastMCP aligns with
  mcp-sdk 2.0, existing deployments will need to verify compatibility.
  [Source: github.com/modelcontextprotocol/python-sdk/releases](https://github.com/modelcontextprotocol/python-sdk/releases)

- **`mcp-types` standalone package:** Protocol types are now published separately as `mcp-types`
  (import: `mcp_types`), depending only on Pydantic. Lightweight clients and validators can use
  this instead of pulling the full transport stack — useful for testing MCP payloads without a
  running server.
  [Source: github.com/modelcontextprotocol/python-sdk/releases](https://github.com/modelcontextprotocol/python-sdk/releases)

- **uv 0.12 defaults to `src/` layout for new projects:** `uv init` now creates packaged projects
  with a `src/` layout and `uv_build` by default (was an unpackaged flat layout). This project
  already follows the `src/` convention — no action needed, but worth knowing for new spinoffs.
  [Source: github.com/astral-sh/uv/releases](https://github.com/astral-sh/uv/releases)

- **uv security hardening:** Recent uv versions reject wheels that could overwrite Python
  interpreters, block case-insensitive reserved names (e.g. `Python.exe`), and drop MD5-only
  hashes in hash-checking mode. Keep uv itself up to date in CI to benefit from these.
  [Source: github.com/astral-sh/uv/releases](https://github.com/astral-sh/uv/releases)

- **Ruff `ruff: ignore` suppression syntax:** As of 0.16.0, inline suppressions can be written as
  `# ruff: ignore[RULE]` (end-of-line or on the preceding line), in addition to the existing
  `# noqa` style. Migrate gradually; both syntaxes are supported.
  [Source: github.com/astral-sh/ruff/releases](https://github.com/astral-sh/ruff/releases)

- **FastAPI SSE module now has official API reference:** The `fastapi.sse` module (including
  `format_sse_event`) is now documented in the official API reference, with spec-compliant
  line-splitting. If the project ever needs Server-Sent Events, this is the canonical way.
  [Source: github.com/tiangolo/fastapi/releases](https://github.com/tiangolo/fastapi/releases)

## Recommendations

**Priority 1 — Security (do this week):**

1. **Update `fastmcp` to 3.4.7.** The JWT audience mismatch fix in 3.4.7 and the JWKS Ed25519
   rejection fix in 3.4.5 are security-relevant for the MCP OAuth layer.
   Command: `uv lock --upgrade-package fastmcp && uv sync`

2. **Update `pydantic-settings` to 2.15.0, but test first.** The symlink fix in
   `NestedSecretsSettingsSource` is a security improvement. However, the behavioral change to
   `case_sensitive` could affect `Settings` initialization; run the test suite and check that
   `Settings.model_validate({})` in `src/config.py` still loads the expected env vars.

**Priority 2 — Routine bug fixes (this sprint):**

3. **Update `fastapi` to 0.141.1.** Pure bug fixes — SSE `status_code`, `response_model_*`
   parameters on Iterable endpoints, and `jsonable_encoder` edge cases.

4. **Update `uvicorn` to 0.52.4.** WebSocket handshake fixes are relevant if the project ever
   exposes WebSocket routes. The new `zttp` parser is opt-in and can remain disabled.

5. **Patch bumps:** `mypy` → 2.3.1, `coverage` → 7.15.4, `pre-commit` → 4.6.2. All safe to
   apply in one `uv lock --upgrade-package <pkg>` pass.

**Priority 3 — Planned (next sprint, requires testing):**

6. **Upgrade `ruff` to 0.16.4 with care.** Run `ruff check .` after the update and review the
   new violations before committing. Many of the 354 newly-enabled rules will fire in typical
   FastAPI code. Update `ruff.toml` to explicitly ignore rules that don't fit this project's
   style, or fix the violations. The new PGO builds are significantly faster.

7. **Monitor FastMCP → MCP 2.0 migration path.** The MCP Python SDK v2.0 introduces a stateless
   protocol that FastMCP will need to adopt. Track the FastMCP changelog; when a 4.x or 3.5.x
   release mentions MCP 2.0 or stateless transport, plan a dedicated upgrade and integration test
   pass (especially for the `/mcp` endpoint's auth middleware).
