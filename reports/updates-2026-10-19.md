## Security

- **`uv audit` did not run.** `make audit` / `uv audit --locked --preview-features
  audit-command` fails in this sandbox with `tunnel error: unsuccessful` querying
  `api.osv.dev`. A direct `curl` to the same host confirms the egress proxy refuses the
  connection (`connect_rejected`, HTTP 403) while `pypi.org` and `github.com` are reachable.
  This is an environment network-policy gap, not a repo issue — re-run `make audit` from CI
  or a machine with OSV access before trusting this week's report as a clean bill of health.
- **`cryptography` (transitive, via `fastmcp`): no open CVE.** Current lock: `50.0.1`. The
  only recent security fix, CVE-2026-69247 (PKCS#7 `RecipientInfo` decryption leaked a
  Bleichenbacher oracle via distinguishable errors/timing), shipped in `50.0.0` — already
  below the repo's current lock. `50.0.2` (available) is a build-only bump (OpenSSL 4.0.2 →
  4.0.3, free-threaded wheels, a PyO3 fix for Cygwin/MSYS2 builds) — (verified via
  `pyca/cryptography` `CHANGELOG.rst`).
- **`fastmcp` 4.0.3 → 4.1.1: five releases of security hardening**, (verified via
  `jlowin/fastmcp` GitHub releases):
  - `4.0.6`: stopped leaking Google access tokens in request URLs; restricted MCP
    "completions" to references the caller can already list.
  - `4.0.8`: reverted the `4.0.6` completion-visibility check after `4.0.7` was found to let
    a response cache leak hidden prompts to other clients.
  - `4.0.11`: broad hardening — safer argument passing to Windows `.cmd` wrappers, bounded
    schema caches/nesting, OpenAPI components restricted to declared arguments, auth applied
    to component-manager routes, **Host/Origin protection added to the SSE transport**, auth
    applied to hashed tool lookups.
  - `4.1.0`: MultiAuth now scopes client IDs by source; shared JWKS refresh across key
    lookups.
  - `4.1.1`: bounded regex-based tool search by pattern length (>1000 chars rejected) and by
    time (~1s), closing a regex-DoS vector.
  - This repo mounts `mcp.http_app()` directly on the public FastAPI app
    (`src/main.py:46-50`) with no `host_origin_protection` or equivalent configured in
    `src/middleware.py` — the Host/Origin guard added in `4.0.11` is directly relevant here
    and isn't available at the currently-pinned `4.0.3`.

## New community practices

- **(unverified)** FastMCP's HTTP transport reportedly offers opt-in Host/Origin request
  validation (a guard separate from CORS) for servers mounted on an existing ASGI app, aimed
  at exactly this repo's setup (`mcp.http_app()` mounted under `/mcp` on the main FastAPI
  app). I could not reach `gofastmcp.com` from this sandbox to confirm the exact API name or
  default state (DNS resolution for that host fails here), but the underlying need is
  corroborated by the *verified* `fastmcp` `4.0.11` release notes above, which added
  "Host/Origin protection" to the SSE transport. Worth confirming against the official docs
  from an unrestricted network before enabling.
- **(unverified, community consensus)** Current FastAPI guidance favors `Annotated[...]` for
  all parameter and dependency declarations, and explicit response models on every path
  operation rather than relying on inferred return types — this repo's single endpoint
  (`src/endpoints/echo.py`) already follows this pattern, so no action needed, just noting it
  as validated existing practice.
- **(unverified, community consensus)** Guidance continues to recommend `uv`'s
  `[dependency-groups]` (PEP 735) over custom "extras" for dev tooling, exactly as this repo
  already does (`[dependency-groups.dev]` in `pyproject.toml`) — again, existing practice
  confirmed rather than a new action.

No other project-specific, actionable practices turned up beyond what's already reflected in
this repo's structure (module layering, pure-function services, resource-layer I/O
isolation) or beyond what the standing decisions in `reference.md` already settle.
