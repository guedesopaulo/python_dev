## New Community Practices

- **MCP 2026-07-28 specification goes stateless**: The largest MCP revision since launch removes the session handshake (`initialize`/`initialized`, `Mcp-Session-Id`). Every request now carries protocol version, client identity, and client capabilities inline in `_meta`. Side benefits: plain round-robin load balancers work without sticky sessions or a shared session store. New primitives include Multi Round-Trip Requests (MRTR), cacheable list responses with `ttlMs`/`cacheScope`, and a Tasks extension for poll-based operations. A twelve-month minimum deprecation window gives teams time to migrate.
  — [MCP Blog: 2026-07-28 Spec](https://blog.modelcontextprotocol.io/posts/2026-07-28/) · [DEV: MCP Went Stateless](https://dev.to/krlz/mcp-went-stateless-what-the-2026-07-28-spec-actually-changes-273k)

- **FastMCP v4 (beta) supports both protocol eras**: FastMCP 4 introduces stateful application logic on a stateless protocol, background tasks, enterprise auth, and interactive tools. One server now negotiates both the 2025 and 2026-07-28 protocol versions per connection. Most FastMCP 3 servers upgrade to v4 without code changes for basic cases.
  — [FastMCP GitHub Releases](https://github.com/PrefectHQ/fastmcp/releases) · [Real Python August 2026](https://realpython.com/python-news-august-2026/)

- **`uv` project-first workflow is now the consensus**: The 2026 community standard is `uv init` → `uv add` → `uv run` → `uv lock`/`uv sync`. Committing `uv.lock` and syncing from it (rather than `requirements.txt`) is the recommended reproducibility strategy. This project already follows this pattern.
  — [DEV: Why uv Became Go-To in 2026](https://dev.to/moksh/why-uv-became-the-go-to-python-package-manager-in-2026-2kag) · [Cuttlesoft: Python Dependency 2026](https://cuttlesoft.com/blog/2026/01/27/python-dependency-management-in-2026/)

- **FastAPI: async def for I/O, def for CPU — strict discipline**: In 2026 this distinction matters more than ever. `async def` endpoints that call synchronous blocking code (e.g., psycopg2, filesystem) degrade the event loop. Use `async def` + `await` for all network I/O; use regular `def` for CPU work and let FastAPI run it in a threadpool automatically.
  — [pratikpathak.com: FastAPI Best Practices 2026](https://pratikpathak.com/fastapi-best-practices-building-production-ready-python-apis-in-2026/)

- **Pydantic v2 discriminated unions are the community standard for polymorphic payloads**: `Annotated` + `Discriminator` replaces ad-hoc `Union` types and brings both faster validation and precise editor hints. The pattern is widely adopted in projects using Pydantic v2 with FastAPI.
  — [DEV: Pydantic v2 Type-Safe](https://dev.to/meroline_lizlent/pydantic-v2-the-data-validation-library-that-makes-python-feel-type-safe-5d0i) · [digon.io: Python 2026 Typing](https://digon.io/en/blog/2026_04_07_python_typing)

## Recommendations

1. **[High] Evaluate FastMCP v4 upgrade path** — FastMCP v4.0.0b3 is the bridge to the 2026-07-28 stateless MCP spec. Since this project exposes MCP tools from FastAPI routes (`FastMCP.from_fastapi`), test the beta in a branch now so the final v4.0.0 release isn't a surprise. The upgrade is mostly backward-compatible for simple tool servers. Track [GitHub Releases](https://github.com/PrefectHQ/fastmcp/releases).

2. **[High] Run `uv lock --upgrade` for minor/patch updates** — `fastapi`, `uvicorn`, `pydantic-settings`, `fastmcp` (3.4.4 → 3.4.7), `mypy`, `coverage`, and `pre-commit` all have newer versions. Run `uv lock --upgrade && uv sync`, then `make all` to verify tests and coverage still pass before committing the updated lockfile.

3. **[Medium] Test ruff 0.16.x before upgrading** — `ruff` 0.16.x introduces new lint rules. Upgrade in isolation (`uv add --dev "ruff>=0.16.3"`), run `uv run ruff check .`, review new violations, and decide on fixes vs. per-rule ignores before bumping the constraint in `pyproject.toml`.

4. **[Medium] Verify MCP endpoint against 2026-07-28 spec** — The `/mcp` mount uses `fastmcp`'s HTTP transport. As clients adopt the new spec, confirm your server handles self-describing requests and is ready to drop session assumptions. FastMCP 3.4.7 maintains backward compatibility, but log what clients send to spot early adopters of the new protocol.

5. **[Low] Consider adding `pydantic-settings` cloud secret sources** — v2.15.0 added optional AWS Secrets Manager, Azure Key Vault, and GCP Secret Manager sources. If this project deploys to a cloud environment, these eliminate manual secret injection and are worth evaluating for the `Settings` class in `src/config.py`.
