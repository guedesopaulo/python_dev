# Weekly Updates Report — 2026-06-22

## Summary

- **FastAPI 0.138.0 is available** (pinned: 0.136.3); the headline addition is a new `app.frontend()` / `router.frontend()` method for serving SPA/static files directly from FastAPI.
- **No direct dependencies carry known security vulnerabilities.** Starlette's high-severity BadHost flaw (CVE-2026-48710) was fixed in Starlette 1.0.1; the project locks Starlette 1.2.1 — not affected.
- **Five packages have newer releases:** fastapi (minor), ruff (patch ×2), pytest (minor), coverage (patch), pydantic-settings (patch). None introduce breaking changes.
- **Ruff 0.15.17–18 add quality-of-life features** worth adopting: human-readable rule names in suppression comments and two new lint rules (RUF076, D421).
- **uv `--frozen` in CI** is the current ecosystem recommendation for reproducible builds; this project does not yet use it.

### Security note — transitive dependency

| Package | Pinned | Vuln fix version | CVE | Status |
|---|---|---|---|---|
| `starlette` *(transitive via fastapi)* | 1.2.1 | 1.0.1 | CVE-2026-48710 (BadHost) | **Not affected** ✓ |

**BadHost (CVE-2026-48710):** Starlette reconstructed `request.url` from an unvalidated HTTP `Host` header, allowing a single injected character (`/`, `?`, `#`) to cause `request.url.path` to diverge from the actual routed path. Middleware or endpoints checking `request.url` for path-based auth could therefore be bypassed silently. Fixed in Starlette 1.0.1 (2026-05-21). This project pins 1.2.1 — no action required.

## New community practices

- **FastAPI `app.frontend()` method** (0.138.0): Mounts a directory of static files (e.g., a built Vite/React app) directly via `app.frontend("/", directory="dist")` without needing separate Starlette StaticFiles boilerplate. Useful if this starter ever grows a UI layer.
  Source: [FastAPI releases](https://github.com/fastapi/fastapi/releases)

- **FastMCP 3 Provider/Transform pattern**: FastMCP 3.0 introduced Providers (where tools come from: decorators, OpenAPI specs, remote MCP servers, filesystems) and Transforms (middleware that renames, filters, or adds auth to tools without touching source code). The pattern decouples tool authoring from tool deployment. Recommended over monolithic server definitions for any FastMCP server that exposes more than a handful of tools.
  Source: [Introducing FastMCP 3.0](https://jlowin.dev/blog/fastmcp-3)

- **FastMCP: annotate tools with `ToolAnnotations`**: The March 2025 MCP specification added `ToolAnnotations` (hints such as `readOnly`, `destructive`, `idempotent`). Annotating every tool lets MCP clients and orchestrators make safer decisions about when to auto-invoke tools.
  Source: [FastMCP updates](https://gofastmcp.com/updates)

- **Ruff human-readable suppression comments** (0.15.17+): Ruff now accepts rule names in `# noqa` comments: `# noqa: missing-return-value` instead of `# noqa: RET504`. Improves code readability and avoids dead suppression comments when rules are renumbered.
  Source: [Ruff CHANGELOG](https://github.com/astral-sh/ruff/blob/main/CHANGELOG.md)

- **uv `--frozen` in CI**: The official uv recommendation for CI environments is `uv run --frozen <cmd>` (or `uv sync --frozen`). This makes the run fail if the lock file is out of date with `pyproject.toml`, guaranteeing reproducible installs rather than silently re-resolving.
  Source: [uv project docs](https://docs.astral.sh/uv/guides/projects/)

- **Pydantic v2: prefer concrete collection types**: Pydantic v2 validates `list[T]` faster than `Sequence[T]`, and `dict[K, V]` faster than `Mapping[K, V]`. Since this codebase uses `TypedDict` for API payloads (as required by CLAUDE.md), prefer the concrete types in field annotations for a free performance win.
  Source: [Pydantic performance docs](https://docs.pydantic.dev/latest/concepts/performance/)

- **pytest-asyncio 1.x: `event_loop` fixture removed**: pytest-asyncio 1.0 (May 2025) removed the deprecated `event_loop` fixture; tests must use `asyncio.get_running_loop()` instead. This project already uses `asyncio_mode = "auto"` in `pyproject.toml` and is compatible.
  Source: [pytest-asyncio 1.0 changelog](https://pytest-asyncio.readthedocs.io/en/v1.0.0/reference/changelog.html)

## Recommendations

Prioritized by impact and effort:

1. **[High — security awareness]** Confirm that `BearerTokenMiddleware` in `src/middleware.py` checks `scope["path"]` (the raw ASGI path) rather than `request.url.path` for any path-based logic. Although the project is not vulnerable to BadHost (Starlette 1.2.1 is pinned), this is the coding pattern that *would* have been exploitable; auditing it now is a low-cost hardening step.

2. **[Medium]** Upgrade `fastapi` to 0.138.0:
   ```bash
   uv lock --upgrade-package fastapi
   uv run pre-commit run --all-files
   uv run pytest
   ```
   No breaking changes are expected; this unlocks the new `app.frontend()` API and stays closer to the security surface of the maintained release.

3. **[Low]** Upgrade remaining outdated packages in one pass:
   ```bash
   uv lock --upgrade-package pydantic-settings \
            --upgrade-package ruff \
            --upgrade-package pytest \
            --upgrade-package coverage
   uv run pre-commit run --all-files && uv run pytest
   ```

4. **[Low]** Add `--frozen` to CI test invocations (e.g., in the `Makefile` `test` target and any GitHub Actions `run:` steps that call `uv run pytest`). This prevents silent lock-file drift in CI.

5. **[Low]** Evaluate adopting FastMCP `ToolAnnotations` on the `/echo` MCP tool and any future tools. Even marking the current tool `readOnly=True` improves interoperability with MCP-aware clients.

6. **[Low]** Consider enabling the new Ruff rule `RUF076` (bans `autouse` fixtures) as a future guard, and update suppression comments to use human-readable names (Ruff 0.15.17+ feature).
