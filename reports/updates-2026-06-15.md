# Weekly Updates Report — 2026-06-15

## Summary

- **Three direct dependencies are outdated**: `fastapi` (0.136.3 → 0.137.1), `pytest` (9.0.3 → 9.1.0), and `ruff` (0.15.16 → 0.15.17); all other pinned packages are at their latest stable release.
- **Critical ecosystem event coming**: The MCP Protocol 2026-07-28 release candidate goes stateless (removes session IDs and the initialization handshake). All MCP servers — including this project's FastMCP integration — must be evaluated and potentially migrated before the spec finalizes on July 28, 2026.
- **FastAPI 0.137.x ships a meaningful router refactoring**: routes are no longer copied on inclusion; `router.routes` is now a reference tree. Upgrading is low-risk for this project but warrants a quick smoke-test.
- **Tooling is healthy**: `pydantic` 2.13.4, `uvicorn` 0.49.0, `httpx` 0.28.1, `mypy` 2.1.0, `coverage` 7.14.1, `pre-commit` 4.6.0, `pytest-asyncio` 1.4.0, `loguru` 0.7.3, and `covdefaults` 2.3.0 are all current.
- **The project already follows key 2026 community best practices**: `uv`-based workflow, Pydantic v2 with TypedDict payloads, `async def` for I/O routes, and structured loguru logging.

## New Community Practices

- **MCP 2026-07-28 spec RC — stateless core**: The upcoming MCP specification removes protocol-level session IDs and the initialization handshake entirely. MCP servers must become horizontally scalable over plain HTTP infrastructure. Background tasks are now scoped to authorization context rather than session. The spec is locked; final release July 28, 2026 after a 10-week validation window. Source: [modelcontextprotocol.io blog](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/)

- **MCP OAuth 2.1 / OIDC alignment**: Six protocol extensions in the RC align authorization with OAuth 2.1 and OpenID Connect (RFC 9207 `iss` parameter validation). Clients will reject authorization responses without `iss`. Currently this project's BearerTokenMiddleware in `src/middleware.py` is a placeholder for cloud envs — now is a good time to plan a proper OIDC implementation. Source: [tokenmix.ai MCP changelog](https://tokenmix.ai/blog/mcp-updates-changelog-every-protocol-change-2026)

- **FastMCP 3.0 provider architecture**: FastMCP 3.x introduces a provider model (filesystem, remote API, per-component authorization, component versioning). `FastMCP.from_fastapi()` usage as in this project remains supported, but new provider patterns unlock richer MCP tool registration. Source: [jlowin.dev FastMCP 3.0 intro](https://jlowin.dev/blog/fastmcp-3)

- **FastAPI router-as-reference (0.137)**: Routes added after `app.include_router()` are now dynamically reflected; routers can be included before child routes are defined. This is a breaking change only for code that iterates `router.routes` and expects flat `APIRoute` objects — such code must handle the new tree structure. Source: [GitHub release 0.137.0](https://github.com/fastapi/fastapi/releases/tag/0.137.0)

- **Ruff 0.15 style guide + new rules**: Ruff 0.15.0 shipped sixteen new stable lint rules, six newly-stabilized behaviors, and a documented formatter style guide. Notable: `RUF073` warns when `%`-formatting is used on an f-string. Source: [astral.sh Ruff 0.15 announcement](https://astral.sh/blog/ruff-v0.15.0)

- **`uv` as unified Python toolchain (2026 consensus)**: The Python community has largely converged on `uv` for install, lock, script execution, and virtual-environment management. Best practices: `uv sync --locked` in CI (this project does this), `uv add` for new deps (vs. hand-editing pyproject.toml), and workspace support for monorepos. Source: [cuttlesoft.com dependency management 2026](https://cuttlesoft.com/blog/2026/01/27/python-dependency-management-in-2026/)

- **Pydantic v2 TypedDict performance pattern**: The community confirms that for API payloads, using `TypedDict` over full Pydantic `BaseModel` subclasses is the recommended performance path in v2 — this project already follows this pattern per CLAUDE.md. Additionally, instantiate `TypeAdapter` once at module level rather than per-request. Source: [pydantic.dev performance docs](https://docs.pydantic.dev/latest/concepts/performance/)

## Recommendations

1. **[HIGH — time-sensitive] Plan for MCP 2026-07-28 spec migration.** Track the FastMCP changelog at [gofastmcp.com/updates](https://gofastmcp.com/updates) for an update that targets the stateless spec. When released, upgrade and run the full test suite against an MCP client before July 28. The `/mcp` endpoint using `streamable-http` transport needs verification under the new stateless model.

2. **[HIGH] Design the cloud auth path in `src/middleware.py`.** The MCP spec RC now mandates OAuth 2.1 / OIDC `iss` validation for authorization flows. The current placeholder comment (`# Cloud envs — placeholder for JWT/OAuth2 validation`) is the right hook point; implement real JWT validation before deploying to `dev`/`qas`/`prod`.

3. **[MEDIUM] Upgrade `fastapi` to 0.137.1.** Run `uv lock --upgrade-package fastapi`, then run the full test suite (`uv run pytest`) and verify the `/echo`, `/health`, and `/mcp` routes work end-to-end. The only risk area is if any code directly iterates `router.routes` — a quick search confirms no such usage in this project.

4. **[LOW] Upgrade `pytest` to 9.1.0.** Straightforward: `uv lock --upgrade-package pytest`. No breaking changes for this project's test patterns; the `config.inicfg` deprecation is for plugin authors, not end users.

5. **[LOW] Upgrade `ruff` to 0.15.17.** `uv lock --upgrade-package ruff`. Run `uv run ruff check . && uv run ruff format .` after upgrading to catch any new rule violations introduced in 0.15.x (especially `RUF073`).

6. **[INFO] Consider enabling additional Ruff rules.** Now that 0.15 is stable, evaluate enabling `RUF073` (f-string percent-format warning) and reviewing the new stable rules for any that fit this project's coding standards. Update `ruff.toml` incrementally.
