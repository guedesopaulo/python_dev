# Weekly Updates Report — 2026-07-27

## Summary

- The project is in excellent shape: 11 of 14 tracked dependencies are already at their latest versions.
- **ruff** has a notable minor update (0.15.21 → 0.16.0) that is potentially breaking: default enabled rules expand from 59 to 413 and Markdown files are now formatted by default.
- **fastapi** and **pre-commit** each have a safe patch update available with no breaking changes.
- The **MCP Python SDK v2.0** (currently in beta) is undergoing a major architectural redesign; tracking its stabilisation is important for future fastmcp compatibility.
- **Pydantic v2.13** dropped Python 3.9 support (irrelevant here since the project requires ≥3.13), and the private-attribute default-factory API gained useful new capabilities.

## New Community Practices

- **MCP Python SDK v2.0 (beta, July 2026)**: Complete architectural redesign — new dispatcher/runner pipeline, `Client(target, mode='auto')` for automatic protocol detection, multi-round tool requests (tools can ask for user input mid-call), OpenTelemetry tracing by default, and a stateless protocol mode from the 2026-07-28 spec revision. WebSocket transport and the experimental tasks API are deprecated.
  Source: <https://github.com/modelcontextprotocol/python-sdk/releases>

- **Ruff 0.16.0 expanded defaults**: The default rule set grows from 59 to 413 rules (documented on a new "Default Rules" page). Projects upgrading should run `ruff check --diff` first to see all new violations before committing. A `# ruff: ignore` comment is now supported as an alternative to `# noqa`.
  Source: <https://github.com/astral-sh/ruff/releases/tag/0.16.0>

- **FastMCP 3.x — remote bridge and structured errors**: `fastmcp-remote` provides a stdio↔HTTP proxy for clients that only support stdio; tools can now return structured errors via the `is_error` parameter; Hugging Face OAuth is natively supported alongside Azure B2C from 3.3.
  Source: <https://github.com/jlowin/fastmcp/releases>

- **Pydantic v2.13 — private-attribute access in default factories**: `PrivateAttr` default factories can now receive the partially-validated model instance, enabling inter-field defaults without `model_post_init`. Python 3.9 support was dropped.
  Source: <https://github.com/pydantic/pydantic/releases>

- **uv centralized environments (0.11.x)**: `uv project` now supports storing environments in a central location with symlinks, improving consistency in monorepo / multi-project setups. Lockfile validation now rejects non-canonically formatted files and regenerates them automatically.
  Source: <https://github.com/astral-sh/uv/releases>

## Recommendations

1. **Update ruff to 0.16.0 (medium priority)**: Run `ruff check --diff` on the codebase first. With 413 default rules the linter may surface new violations. Review and either fix them or add explicit `ignore` entries in `ruff.toml` before pinning the new version. Note that the current `ruff.toml` suppresses UP040 for mypy compatibility — verify that exemption is still needed.

2. **Update fastapi to 0.140.0 (low priority)**: A pure patch update with a memory optimisation for dependency injection. Safe to run `uv lock --upgrade-package fastapi` and merge.

3. **Update pre-commit to 4.6.1 (low priority)**: Patch-level bug fixes. Safe to run `uv lock --upgrade-package pre-commit` and merge.

4. **Track MCP Python SDK v2.0 stabilisation (medium priority)**: The v2.0 beta deprecates WebSocket transport and redesigns the core session model. fastmcp will likely update its own dependency and may ship its own breaking changes. Subscribe to the fastmcp release feed to catch this early.

5. **Consider `uv lock --upgrade` as a periodic CI step**: With most deps already current, a scheduled `uv lock --upgrade` run in CI would catch future drift before it accumulates.
