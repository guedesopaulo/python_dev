# Weekly Updates Report — 2026-07-06

## Summary

- **Security alert**: FastMCP 3.4.3 (pinned: 3.4.2) patches SSRF, DNS-rebinding, and OAuth
  redirect vulnerabilities — upgrade is the top priority this week.
- **5 dependencies are behind**: fastmcp, fastapi, uvicorn, ruff, and coverage all have newer
  releases available; none are breaking changes relative to the current pins.
- **Uvicorn 0.50.x** brings meaningful performance wins (memoised trusted-host checks, ASGI scope
  caching) and deprecates the legacy `websockets` implementation.
- The FastMCP ecosystem continues rapid development; 3.4.x adds a `fastmcp-remote` bridge,
  OpenTelemetry support, and structured tool errors — all directly relevant to this project.
- Community momentum is firmly behind **uv** for dependency management; pinning the uv version in
  CI is now considered a standard practice.

## New Community Practices

- **Pinning the `uv` version in CI** — community consensus has settled on specifying an exact `uv`
  version in CI workflows (e.g., `astral-sh/setup-uv@v5` with a pinned `uv-version`) to prevent
  silent toolchain drift. This project's CI (if any) should adopt this.
  [Source](https://www.loopwerk.io/articles/2026/uv-ux-mess/)

- **FastMCP OpenTelemetry integration** — FastMCP 3.x ships built-in OpenTelemetry tracing for
  every tool call, resource access, and JSON-RPC message. This is now the recommended way to gain
  production observability on MCP servers, replacing ad-hoc logging.
  [Source](https://gofastmcp.com/getting-started/welcome)

- **Streamable HTTP with TLS as the MCP production transport standard** — the 2026 MCP spec
  formalises streamable HTTP (already in use here via `/mcp` mount) as the remote-server default.
  Local stdio remains the standard for desktop hosts.
  [Source](https://tech-insider.org/mcp-server-tutorial-python-fastmcp-claude-2026/)

- **`TypeAdapter` + `TypedDict` for Pydantic v2 validation** — using `TypeAdapter(MyTypedDict)` is
  now the idiomatic pattern for validating structured payloads that don't need full `BaseModel`
  machinery, aligning with the project's existing `TypedDict`-first convention.
  [Source](https://docs.pydantic.dev/latest/concepts/models/)

- **`async def` only for real I/O; `def` for CPU-bound FastAPI routes** — FastAPI runs sync
  endpoints in a thread pool automatically, so forcing `async def` on CPU-bound handlers
  serialises them on the event loop. The rule: use `async def` only when you `await` something.
  [Source](https://dasroot.net/posts/2026/01/building-high-performance-apis-fastapi-async-python/)

- **`fastmcp-remote` for bridging stdio hosts to HTTP MCP servers** — introduced in FastMCP 3.4.0,
  this standalone utility lets stdio-only MCP clients (e.g., Claude Desktop) connect to remote
  Streamable HTTP servers without a proxy. Relevant if this project ever exposes its MCP endpoint
  to desktop clients.
  [Source](https://github.com/PrefectHQ/fastmcp/releases)

## Recommendations

Priority order (highest first):

1. **[HIGH — Security] Upgrade `fastmcp` to 3.4.3.**
   Run `uv lock --upgrade-package fastmcp` and re-run the test suite. The 3.4.3 release closes
   SSRF and DNS-rebinding vectors that are exploitable on any server that proxies or fetches
   upstream MCP content. Even with `BearerTokenMiddleware` in place, the `/mcp` route is an
   attack surface.

2. **[MEDIUM] Upgrade `uvicorn` to 0.50.2.**
   Run `uv lock --upgrade-package uvicorn`. The performance improvements (memoised host checks,
   scope caching) are free wins, and aligning with the `websockets-sansio` default avoids a future
   forced migration when the legacy implementation is removed.

3. **[LOW] Upgrade `fastapi`, `ruff`, and `coverage`.**
   All are non-breaking patch/minor bumps. Batch them: `uv lock --upgrade-package fastapi
   --upgrade-package ruff --upgrade-package coverage`. Run `make check` and `make test`
   afterwards.

4. **[LOW] Pin the `uv` version in CI.**
   Add `uv-version: "0.7.x"` (or the specific version in use) to any CI setup steps. This
   prevents silent toolchain changes from affecting reproducibility of `uv lock` runs.

5. **[INFORMATIONAL] Evaluate FastMCP OpenTelemetry integration.**
   As the MCP surface grows beyond the single `/echo` tool, consider instrumenting the server
   with FastMCP's built-in OTel tracing. This requires no code changes beyond configuration and
   gives per-call traces in any OTel-compatible backend.
