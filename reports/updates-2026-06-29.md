## New Community Practices

- **FastMCP 3.x OpenTelemetry integration**: FastMCP 3.0 (January 2026) shipped built-in OpenTelemetry traces for every tool call and JSON-RPC message. For a production MCP server this is now the recommended observability approach — no third-party tracing library needed. ([FastMCP docs](https://gofastmcp.com/getting-started/welcome), [KDnuggets overview](https://www.kdnuggets.com/fastmcp-the-pythonic-way-to-build-mcp-servers-and-clients))

- **FastMCP 3.x authorization controls**: Version 3.0 also added per-tool authorization hooks. The current repo exposes `/mcp` behind `BearerTokenMiddleware` at the ASGI level, which works well; per-tool controls are a finer-grained option worth considering if individual tools gain different trust requirements. ([MCP.Directory comparison](https://mcp.directory/blog/fastmcp-vs-fastapi-mcp-vs-python-sdk-2026))

- **uv lockfile in CI for reproducibility**: The Astral team now recommends committing `uv.lock` and running `uv sync --frozen` in CI (rather than bare `uv sync`) to guarantee byte-for-byte reproducibility and prevent silent drift. The project already commits `uv.lock`; adding `--frozen` to CI scripts is the remaining step. ([uv GitHub](https://github.com/astral-sh/uv))

- **Pydantic `TypeAdapter` for lightweight validation**: When you need to validate or serialize a plain `dict` or `TypedDict` without a `BaseModel`, `TypeAdapter` is now the idiomatic Pydantic v2 approach — it avoids subclassing overhead and aligns with the project's existing preference for `TypedDict`. ([Pydantic performance docs](https://docs.pydantic.dev/latest/concepts/performance/))

- **PEP 695 type alias syntax (`type X = ...`)**: Python 3.13 fully supports `type Alias = ...` and `def f[T](x: T) -> T`. Ruff rule `UP040` flags old-style `TypeAlias` usage, but the project intentionally ignores `UP040` because mypy 2.x still has partial PEP 695 support. Mypy 2.1.0 (pinned) has improved handling — worth evaluating whether `UP040` can be re-enabled. ([PEP 695](https://peps.python.org/pep-0695/), [Python 3.12 whatsnew](https://docs.python.org/3/whatsnew/3.12.html))

- **Ruff human-readable rule selectors (preview)**: Ruff 0.15.20 preview allows writing `select = ["unused-import"]` instead of `"F401"` in `ruff.toml`. Opt in with `preview = true` when the feature stabilises. ([Ruff releases](https://github.com/astral-sh/ruff/releases))

## Recommendations

Ordered by priority:

1. **Upgrade `coverage` to 7.14.3** (`uv lock --upgrade-package coverage`). The fix for multi-line return-type annotations directly affects Python 3.13 projects with modern type hints, which this codebase uses heavily. Low risk — patch release.

2. **Upgrade `ruff` to 0.15.20** (`uv lock --upgrade-package ruff`). Two-patch jump with performance gains and bug fixes for editor integrations; no rule removals that affect this project's config (the removed preview rule `RUF076` is not in the selected set).

3. **Upgrade `fastapi` to 0.138.1** (`uv lock --upgrade-package fastapi`). Pure housekeeping patch; useful to keep the lock file current even though there are no user-visible changes.

4. **Add `--frozen` to CI `uv sync` calls** (`uv sync --frozen` in scripts/CI). Prevents CI from silently upgrading transitive deps between lock-file updates. No code change required — only script/Makefile adjustment.

5. **Evaluate `uv sync --frozen` and `uv audit` in pre-commit**: Astral's `uv audit` command (experimental as of 0.x) checks packages against OSV — worth adding to `pre-commit` hooks once it stabilises, replacing or augmenting `bandit`.

6. **Revisit `UP040` ruff ignore**: With mypy 2.1.0 now shipping improved PEP 695 support, run `uv run mypy .` after removing `UP040` from the ignore list to see how many new-style type aliases would be flagged. If clean, enable the rule.

7. **Explore FastMCP OpenTelemetry tracing**: For visibility into MCP tool call latency in production, enable the OTel integration available in FastMCP 3.x. The current project already wires the FastMCP lifespan through FastAPI — the OTel setup would be a small addition to `src/main.py`.
