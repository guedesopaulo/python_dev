# Weekly Updates Report — 2026-07-13

## Summary

- **Security alert**: `fastmcp` 3.4.2 → 3.4.4 is the most urgent upgrade; 3.4.3 patched SSRF, DNS rebinding, and OAuth redirect vulnerabilities that affect the MCP server running in this project.
- **Mypy is pinned** with `==2.1.0` and is two minor versions behind (2.3.0); unlocking the pin enables closed TypedDicts (PEP 728) and TypeVar defaults (PEP 696), both directly relevant to the codebase's type-safety goals.
- `uvicorn` 0.49.0 → 0.51.0 adds near-zero-downtime worker reloads on `SIGHUP` and WebSocket/performance improvements.
- Three routine patch upgrades are ready: `fastapi` (0.138.0→0.139.0), `coverage` (7.14.2→7.15.1), and `ruff` (0.15.18→0.15.21).
- Everything else (`loguru`, `pydantic-settings`, `httpx`, `pydantic`, `pytest`, `pytest-asyncio`, `covdefaults`, `pre-commit`) is already at the latest release.

## New Community Practices

- **Closed TypedDicts (PEP 728, mypy 2.2+)**: TypedDicts can be declared with `total=False, closed=True` (or `@typing.final`) to forbid extra keys at type-check time. This is directly applicable to the project's API payload types, tightening structural typing without runtime cost.
  *Source: https://mypy.readthedocs.io/en/latest/typed_dict.html*

- **FastMCP SSRF hardening (3.4.3)**: The MCP ecosystem now explicitly blocks tunnelling private IPv4 addresses through IPv6 transition mechanisms (NAT64, 6to4, Teredo, ISATAP). Servers on localhost also gain DNS rebinding protection. Projects exposing MCP over HTTP should treat 3.4.2 → 3.4.4 as a security-critical upgrade.
  *Source: https://github.com/jlowin/fastmcp/releases/tag/3.4.4*

- **Uvicorn near-zero-downtime reloads (0.51)**: Sending `SIGHUP` to a uvicorn process now restarts workers with overlap rather than killing them first. Useful for production deployments that want graceful rollover without a process manager like gunicorn.
  *Source: https://github.com/encode/uvicorn/releases/tag/0.51.0*

- **pytest-asyncio 1.x stable**: The 1.x line (1.4.0 is latest) is a major redesign from the 0.x series, with Python 3.10–3.14 support, first-class support for `asyncio_mode = "auto"`, and improved fixture scoping. The project is already on 1.4.0 — staying current here is low-friction.
  *Source: https://pypi.org/project/pytest-asyncio/*

- **Ruff `--add-ignore` flag (0.15.19+)**: Ruff can now insert `# ruff: noqa` comments in-place via `--add-ignore`, reducing friction for targeted rule suppression in legacy code paths.
  *Source: https://github.com/astral-sh/ruff/releases*

## Recommendations

Ordered by priority:

1. **[Critical] Upgrade `fastmcp` 3.4.2 → 3.4.4** (`pyproject.toml` + `uv lock`).
   The current version is exposed to SSRF and DNS rebinding attacks on the MCP endpoint. Run `uv add fastmcp>=3.4.4` and re-run the test suite; the 3.4.4 release explicitly restores backward compatibility with ASGI and reverse-proxy setups like the one in this project (`/mcp` mounted under FastAPI).

2. **[Important] Unpin and upgrade `mypy` 2.1.0 → 2.3.0**.
   Change `"mypy==2.1.0"` to `"mypy>=2.3.0"` in `pyproject.toml`. Mypy 2.2 added closed TypedDicts (PEP 728) — once on 2.3, annotate API payload TypedDicts as closed to prevent accidental extra-key bugs. Verify that no existing annotations break under `--local-partial-types` (already on by default since mypy 2.0).

3. **[Moderate] Upgrade `uvicorn` 0.49.0 → 0.51.0**.
   Run `uv add uvicorn>=0.51.0`. Zero-downtime SIGHUP reloads are immediately useful for any deployment scenario. No breaking changes expected.

4. **[Routine] Patch upgrades**: bump `fastapi>=0.139.0`, `coverage>=7.15.1`, `ruff>=0.15.21` via `uv add` or `uv lock --upgrade-package`. These are safe patch updates with no breaking changes.

5. **[Enhancement] Adopt closed TypedDicts** after upgrading mypy. In `src/endpoints/echo.py` and any future API payload types, add `closed=True` (mypy 2.2+) to TypedDicts to prevent structural drift as new fields are added.

6. **[CI] Add `uv lock --check`** to CI pipeline to detect out-of-sync lock files on every PR, preventing the gap between declared versions and resolved versions that this report surfaced.
