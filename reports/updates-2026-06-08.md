## New Community Practices

- **CVE-2026-48710 "BadHost" — Starlette host-header auth bypass**: A malformed `Host` header can cause `request.url.path` to diverge from the actual routed path, allowing unauthenticated bypass of middleware and endpoint guards. Affects Starlette < 1.0.1. Fixed in 1.0.1+ (May 21 2026). This project uses 1.2.1 and is protected. Any team still on FastAPI < 0.111 (which depends on Starlette < 1.0) should upgrade immediately.
  — [badhost.org](https://badhost.org/), [CSO Online](https://www.csoonline.com/article/4177711/fastapi-based-ai-tools-exposed-to-authentication-bypass-by-flaw-in-starlette-framework.html)

- **FastMCP 3.0 Components/Providers model**: The 3.0 release (GA Feb 18 2026) introduces a Components (tools, resources, prompts) + Providers architecture, per-component authorization scopes, native OpenTelemetry tracing, and parallel async tool dispatch. Decorated functions remain directly callable for unit testing. Backward-compatible — most projects upgraded with zero code changes.
  — [jlowin.dev/blog/fastmcp-3](https://jlowin.dev/blog/fastmcp-3), [jlowin.dev/blog/fastmcp-3-whats-new](https://jlowin.dev/blog/fastmcp-3-whats-new)

- **MCP Specification 2026-07-28 Release Candidate**: The Model Context Protocol has published a specification release candidate targeted at July 28 2026, potentially introducing protocol-level changes. Libraries such as fastmcp and the mcp Python SDK will need to track and implement these changes.
  — [blog.modelcontextprotocol.io](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/)

- **uv as the 2026 Python project standard**: `uv` has emerged as the consensus package manager, replacing pip/Poetry for most new projects. Key CI practice: use `uv sync --frozen` (never auto-update the lock in CI) and cache the uv store between runs. The project already follows this model.
  — [Real Python — Managing Python Projects With uv](https://realpython.com/python-uv/), [Scopir 2026 comparison](https://scopir.com/posts/best-python-package-managers-2026/)

- **Pydantic v2 TypedDict over nested BaseModel for performance**: For pure data-transfer objects, `TypedDict` avoids Pydantic's validation overhead while preserving type safety. Pydantic v2 supports `@with_config` for TypedDict configuration. The project's `CLAUDE.md` already mandates `TypedDict` for structured payloads — consistent with this guidance.
  — [Pydantic performance docs](https://docs.pydantic.dev/latest/concepts/performance/), [Speakeasy TypedDict vs Pydantic](https://www.speakeasy.com/blog/pydantic-vs-dataclasses)

- **PEP 728 closed TypedDict**: PEP 728 adds `closed=True` and `extra_items` to `TypedDict` for stricter structural typing. Currently requires `from typing_extensions import TypedDict`. Not yet universally supported by type checkers, but worth tracking as it hardens API payload contracts.
  — [Pydantic Standard Library Types](https://docs.pydantic.dev/latest/api/standard_library_types/)

- **FastAPI async pitfalls — blocking calls in async routes**: Community guidance continues to emphasize that mixing `async def` routes with blocking libraries (e.g. `requests`, `time.sleep`, synchronous DB drivers) serializes the event loop. Offload CPU-bound work to `asyncio.run_in_executor` or `anyio.to_thread.run_sync`.
  — [pratikpathak.com FastAPI async 2026](https://pratikpathak.com/fastapi-async-production-practices/)

## Recommendations

Listed by priority.

1. **[High] Watch for fastmcp update tracking the MCP 2026-07-28 spec RC.** The MCP specification RC introduces potential protocol-level changes. When fastmcp publishes a release that implements the new spec, upgrade promptly to avoid client/server incompatibilities. Subscribe to [fastmcp releases](https://github.com/jlowin/fastmcp/releases) and the [MCP blog](https://blog.modelcontextprotocol.io/).

2. **[Medium] Add `bandit` to `pyproject.toml` dev dependencies.** Bandit is currently pinned only in `.pre-commit-config.yaml` (rev 1.9.4) and runs in an isolated pre-commit virtualenv. Adding it to `[dependency-groups].dev` brings it under uv's resolver, enables `uv run bandit` for ad-hoc scans, and makes the version visible in `uv.lock`. Suggested addition: `"bandit>=1.9.4"`.

3. **[Medium] Keep `.pre-commit-config.yaml` rev pins in sync with `pyproject.toml`.** The ruff (`v0.15.16`) and mypy (`v2.1.0`) revs currently match their pyproject.toml counterparts — maintain this discipline on every future upgrade to avoid silent tool-version skew between pre-commit runs and `uv run` invocations.

4. **[Low] Explore FastMCP 3.x per-component authorization.** FastMCP 3.0 introduced fine-grained authorization scopes at the tool/resource/prompt level. The project currently applies a single bearer token via `BearerTokenMiddleware`; consider whether per-tool auth granularity would benefit production deployments.

5. **[Low] Evaluate FastMCP 3.x OpenTelemetry instrumentation.** FastMCP 3.0 ships native OTEL tracing for every tool call, resource read, and prompt render. If observability becomes a requirement, this is now zero-config rather than manual instrumentation.

6. **[Low] Track PEP 728 `closed` TypedDict adoption.** Once `mypy` fully supports PEP 728 (currently in `typing_extensions`), adopt `closed=True` on API payload TypedDicts to prevent extra-key injection at the type-checker layer. No code change needed today; file a future task.
