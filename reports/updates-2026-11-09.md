## Security

- `make audit` (`uv audit --locked --preview-features audit-command`) failed before
  producing a result: `error sending request for url (https://api.osv.dev/v1/querybatch)` /
  `tunnel error`. The session's proxy status endpoint confirms this is a policy denial
  (`connect_rejected`, `gateway answered 403 to CONNECT`, host `api.osv.dev:443`), not an
  application error. **Re-run `make audit` in CI or a session with OSV access before trusting
  this week's dependency set is CVE-free; do not treat the absence of a finding here as a
  clean result.**
- As a partial substitute, release notes were checked by hand for the two packages that have
  caused CVE surprises in past reports (per `reference.md` failure mode #1):
  - `cryptography` 50.0.1 (current) is past CVE-2026-69247 (fixed in 50.0.0; verified against
    `pyca/cryptography`'s `CHANGELOG.rst`). 50.0.2 (available) is a wheel/OpenSSL-version bump
    only, no CVE. **Clean.**
  - `pydantic` 2.13.5 (current, transitive) is missing 4 GHSA fixes shipped in 2.14.0–2.14.3
    (verified against `pydantic/pydantic`'s GitHub releases — see Outdated dependencies).
    **Flagged above; not independently confirmed exploitable in this app's usage, since none
    of `pydantic`'s advisories here concern `BaseSettings`/`loguru`/the echo endpoint's
    `TypedDict` shape, but it's a free, no-code-change fix.**
- No other dependency in the lockfile was checked by hand; this is not a substitute for a
  real `uv audit` run.

## New community practices

- FastMCP's own guidance for network-exposed servers treats authentication as mandatory and
  recommends Streamable HTTP (over stdio) for multi-client/web deployments (verified against
  the FastMCP changelog and docs via search). This repo already does both: `/mcp` is excluded
  from `BearerTokenMiddleware`'s public paths and the server uses
  `mcp.http_app(transport="http", path="/")` — no action, just confirms the current setup
  matches current guidance. (verified)
- uv's PEP 735 `[dependency-groups]` table (not the deprecated `[tool.uv] dev-dependencies`)
  is the current recommended way to declare dev dependencies (verified against uv docs via
  search summary) — this repo's `pyproject.toml` already uses `[dependency-groups] dev = [...]`.
  No action. (verified)
- FastAPI/Pydantic-v2 guidance favors declaring `Depends()` via `Annotated` type aliases
  (e.g. a shared `RateLimited = Annotated[None, Depends(rate_limit(...))]`) over the
  default-value form, for reuse and clarity (verified against FastAPI's own dependency-injection
  docs via search). `src/dependencies.py` currently returns a plain callable used as
  `dependencies=[Depends(rate_limit(30, 60))]`; switching to an `Annotated` alias per limiter
  would match current guidance but is a style choice, not a bug — flagged as a minor
  recommendation below, not a correctness issue. (verified)
- Community sources discuss FastAPI/FastMCP skills-for-coding-agents distribution (FastAPI
  0.162.2 ships an official "FastAPI skill" installable via `uvx library-skills`, and FastMCP's
  SEP-2640 Skills extension). Neither is relevant to this repo's current scope (single `/echo`
  endpoint, no agent-skill distribution), so no action — noted for awareness only. (verified,
  via FastAPI/FastMCP release notes)

## Recommendations

1. **Re-run `make audit` somewhere with `api.osv.dev` reachable (plain CI, or a session
   without this egress restriction) before the next release.** This week's report cannot
   make a CVE claim one way or the other for the full dependency set — only the two
   transitives with known past CVE history were checked by hand. *Why it matters here*: this
   repo's own CI job (`check`) runs `uv audit` on every PR with unrestricted network access,
   so the gate itself is not broken — only this report's own ability to preview it is.
2. **Bump the direct dependencies** (`fastapi`, `fastmcp`, `pydantic-settings`, `starlette`,
   `uvicorn`) together, which pulls `pydantic` to 2.14.3 and closes the 4 GHSA fixes listed
   above at no extra cost. *Why*: it's the only item this week with an actual security
   advisory attached, and it requires no `pyproject.toml` floor changes since all floors are
   already satisfied by the new versions.
3. **Bump `mypy` and `mirrors-mypy` together** (2.3.1 → 2.4.1) to keep the lock-step the
   standing decision requires. *Why*: leaving them pinned at the old patch indefinitely isn't
   the intent of the decision — only drifting them apart is.
4. **Bump `uv`'s three pins together** (Dockerfile, `ci.yml`, `uv-pre-commit` rev) to 0.13.7.
   *Why*: `reference.md` explicitly calls out uv-itself drift as something the automated audit
   can't see, and all three are currently consistent with each other, so this is a clean,
   low-risk three-file bump.
5. **Bump `actions/checkout` and `astral-sh/setup-uv`**, reading each action's own release
   notes for the major-version jump before merging (v6→v7.0.1, v8.2.0→v10.3.3). *Why*: these
   are the two tooling pins with a major-version gap, the one case in this report where a
   version-number bump alone isn't enough diligence.
6. **Optional, low priority**: consider `Annotated`-style `Depends()` aliases in
   `src/dependencies.py` to match current FastAPI guidance. *Why*: purely stylistic for a
   single-limiter codebase today, but establishes the pattern before more endpoints are added.
