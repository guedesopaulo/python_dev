# Weekly updates report — 2026-09-21

## Summary

- **No known vulnerabilities** in the locked dependency set (105 packages, direct and transitive). `uv audit`'s OSV backend (`api.osv.dev`) is unreachable from this sandbox's egress policy, so this was cross-verified per-package against PyPI's own vulnerability feed instead — see [Security](#security) for the caveat.
- `cryptography` — previously flagged in this repo's report history as a transitive of `fastmcp` that silently accumulated CVEs — is at `50.0.1`, already the latest version, with zero reported vulnerabilities.
- 4 direct dependencies are outdated, all patch/minor, no breaking changes found: `fastmcp` (4.0.3→4.0.5), `uvicorn` (0.52.4→0.53.0), `ruff` (0.16.6→0.16.8), `coverage` (7.16.0→7.16.1). 14 transitive packages are also behind (see table).
- `uv` itself is one patch release behind (0.12.10→0.12.17) in all three places it's pinned (Dockerfile, CI, pre-commit); the newer release adds wheel/sdist hash verification, a genuine supply-chain-security improvement worth picking up.
- `astral-sh/setup-uv` (the GitHub Action, distinct from the `uv` version it installs) is two majors behind (v8.2.0→v10.1.0); the major bumps are cache-behavior changes that don't affect this repo's current CI triggers.

## Security

- `make audit` could not be run against its real backend: `uv audit --locked --preview-features audit-command` calls `api.osv.dev`, which this sandbox's egress policy blocks (`tunnel error: unsuccessful`). This is an environment limitation, not a repo problem — CI runs with full network access and remains the authoritative gate.
- As a substitute, every one of the 105 packages in `uv.lock` (direct and transitive) was checked individually against `https://pypi.org/pypi/<name>/<version>/json`, whose `vulnerabilities` field is itself sourced from OSV. **Result: zero vulnerabilities found** at the currently locked versions.
- This directly addresses the reference doc's known failure mode #1 (transitive blindness, exemplified by `cryptography`): `cryptography==50.0.1` is checked, current, and clean.
- No CVE was found tied to any of the version bumps below. `fastmcp` 4.0.4 did harden its `OAuthProxy` (reject ID-JAG tokens when identity assertion isn't configured; reject non-positive upstream token expiries) — a proactive hardening, not a disclosed vulnerability fix. Relevant context for this repo since `src/middleware.py`'s cloud-environment JWT/OAuth2 validation is still a documented placeholder.

## New community practices

- **uv now verifies package hashes at install time.** As of `uv` 0.12.16, downloaded wheels and sdists are checked against the hashes package indexes supply, closing a gap versus lockfile-only hash pinning. (verified — [uv releases](https://github.com/astral-sh/uv/releases))
- **`setup-uv` v10 disables GitHub Actions caching by default on cache-poisoning-prone triggers** (`pull_request_target`, `workflow_run`, `release`). Doesn't change this repo's behavior today (`ci.yml` only runs on `push`/`pull_request`), but is a reason to bump rather than stay pinned indefinitely. (verified — [astral-sh/setup-uv releases](https://github.com/astral-sh/setup-uv/releases))
- **FastMCP's `OAuthProxy` now rejects unconfigured ID-JAG identity assertions and non-positive upstream token expiries** (v4.0.4). Worth reviewing before implementing the `src/middleware.py` cloud-environment JWT/OAuth2 placeholder, alongside FastMCP's own guidance to validate token audience and cache JWKS lookups rather than hitting the authorization server per request. (verified — [FastMCP releases](https://github.com/jlowin/fastmcp/releases), [FastMCP auth docs](https://gofastmcp.com/servers/auth/authentication))
- **Ruff 0.16.8 recognizes PEP-728 `TypedDict` class keywords** (`closed=True`, extra-items typing) on Python 3.13+. Not currently used by this repo's one `TypedDict` (`EchoResponse` in `src/endpoints/echo.py`), so informational only — no action needed unless a future endpoint needs a closed/partial payload shape. (verified — [ruff CHANGELOG](https://raw.githubusercontent.com/astral-sh/ruff/main/CHANGELOG.md))

## Recommendations

1. **Bump the three `uv` pins together** (Dockerfile, `ci.yml`, `.pre-commit-config.yaml`) from `0.12.10` to `0.12.17` — keeps them in lock-step per this repo's own convention and picks up wheel/sdist hash verification.
2. **Bump the four outdated direct/dev dependencies** (`fastmcp`, `uvicorn`, `ruff`, `coverage`) and run `uv lock` to pick up the 14 outdated transitives automatically; none of the release notes reviewed show breaking changes for this repo's usage.
3. **Bump `astral-sh/ruff-pre-commit` to `v0.16.8`** alongside the `ruff` dev-dependency bump, so the hook and the dependency stay in agreement (the same rationale CLAUDE.md already applies to `mypy`/`mirrors-mypy`).
4. **Bump `astral-sh/setup-uv` to `v10.1.0`** (and `crate-ci/typos` to `v1.50.2`, `docker/setup-buildx-action` to `v4.4.1`, `docker/build-push-action` to `v7.4.0`) — all patch/minor with no breaking changes found; `setup-uv`'s major bumps are cache-poisoning hardening that costs nothing here.
5. **Optional: `actions/checkout` to `v7`** — no forcing reason found; the repo's `@v6` moving tag already gets patches automatically, unlike `setup-uv` which is deliberately full-pinned. Leave for a maintainer call.
6. **When implementing the cloud-env auth placeholder in `src/middleware.py`,** revisit FastMCP's v4.0.4 `OAuthProxy` hardening and its audience/JWKS-caching guidance first, since the `fastmcp` bump above will already carry it.
