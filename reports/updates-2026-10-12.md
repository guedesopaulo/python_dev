# Weekly updates report — 2026-10-12

## Summary

- **Two confirmed, unmerged Dependabot security PRs sitting open since 2026-10-01 (11 days):
  #29 (`pyjwt` 2.13.0→2.15.0) and #30 (`virtualenv` 21.7.8→21.7.13).** GitHub's push output
  for this branch also reports 17 open vulnerability alerts on `main` (1 critical, 8 high, 8
  moderate) — this report could not enumerate all 17 (no API access to the alerts list from
  this session), but independently verified the two with open fix PRs via their GHSA
  advisories (below). **Merging #29 and #30 is this week's top action.**
- **`virtualenv` 21.7.8 (dev-only, pulled in by `pre-commit`) carries at least two High-severity
  command-injection advisories** — GHSA-x78j-v8h9-3j2q (`activate.bat --prompt` injection,
  fixed 21.7.12) and GHSA-p58f-9548-mpm2 (bash/fish activation injection via embedded paths,
  fixed 21.7.13) — both verified against their advisory pages. PR #30 already fixes both.
- **The `uv` pin (0.12.10, used identically in the Dockerfile, the `uv-pre-commit` rev, and
  CI's `setup-uv` `version:`) falls inside the affected range of GHSA-2cv4-cqwr-gwf7**, a
  Moderate Windows-only path-traversal-through-wheel-extraction advisory (affects
  0.12.7–0.12.17, fixed in 0.12.18). Calibrated to this repo: CI runs on `ubuntu-latest` and
  the Docker build is Linux-only, so production/CI exposure is low; it matters only if any
  contributor runs the documented "uv on the host" dev loop on Windows. Still a one-line fix.
- **`make audit` could not run this cycle.** `uv audit` needs `api.osv.dev`, which this
  sandbox's egress policy blocks (`tunnel error: unsuccessful`, confirmed on two attempts).
  GitHub's own Dependabot alerts (above) are this week's substitute ground truth — re-run
  `uv audit` in CI (where it already gates every PR) before relying on "no known CVEs."
- **Security-relevant transitive bump available: `pyjwt` 2.13.0 → 2.15.1.** The 2.14.0
  release alone fixes 11 GHSA advisories (HMAC key-confusion/validation hardening, JWKS
  redirect rejection, recursion-based DoS). It only surfaces via the full `uv lock --upgrade`
  cross-check — a targeted `uv lock --upgrade-package` would miss it, which is exactly the
  "blind to transitives" failure mode `reference.md` already warns about.
- **`fastmcp` 4.0.3 → 4.1.0** carries several security fixes across the 4.0.6–4.0.11 patch
  releases (SSE Host/Origin hardening, OAuth upstream-token leakage/revocation fixes, a
  completion-cache fix that could expose hidden prompts). This repo mounts FastMCP's
  streamable-HTTP app directly, so these fixes apply here.
- Routine minor/patch bumps are available for `fastapi`, `starlette`, `uvicorn`, `coverage`,
  `ruff`, and `cryptography` — none carry a breaking change that affects this repo's actual
  config (checked against `ruff.toml`'s explicit `select` list and this repo's own
  `filterwarnings`/middleware setup).
- `docker/build-push-action` v7.3.0 → v7.4.0 fixes a workflow-command-injection issue in
  metadata logs (verified in the v7.4.0 release notes, no CVE/GHSA assigned).

## Security

- `make audit` (`uv audit --locked --preview-features audit-command`) failed both times it
  was run: `error sending request for url (https://api.osv.dev/v1/querybatch) ... tunnel
  error: unsuccessful`. The CI `check` job runs the same command with (presumably)
  unrestricted egress, so CI remains the authoritative audit gate — this report cannot add a
  second independent confirmation of a clean scan this week.
- **Substitute ground truth: GitHub Dependabot.** Pushing this report's branch surfaced
  GitHub's own banner — 17 open vulnerability alerts on `main` (1 critical, 8 high, 8
  moderate) — and the repo already has two open, unmerged Dependabot *security* PRs (not
  subject to the `open-pull-requests-limit: 0` setting, which only throttles version-update
  PRs):
  - **#29 — `pyjwt` 2.13.0 → 2.15.0**, open since 2026-10-01. Confirmed: 2.14.0 fixes 11 GHSA
    advisories (HMAC key-confusion hardening, JWKS-redirect rejection, recursion DoS).
  - **#30 — `virtualenv` 21.7.8 → 21.7.13**, open since 2026-10-01. Confirmed via
    `pypa/virtualenv`'s advisory list: `virtualenv` 21.7.8 is in the affected range of at
    least GHSA-x78j-v8h9-3j2q (High — `activate.bat --prompt` command injection, fixed
    21.7.12) and GHSA-p58f-9548-mpm2 (High — bash/fish activation command injection via
    embedded paths, fixed 21.7.13). Several older High-severity activation-script GHSAs
    exist for this project too (GHSA-vxj4-q4g9-crj7, GHSA-5vjq-rrrf-7h2q,
    GHSA-c947-3pg5-gm8q, GHSA-8rjx-v5ww-45pp) but their exact affected ranges weren't
    individually checked this cycle — budget for a follow-up if #30 doesn't land soon.
  - This report's own predecessor (PR #31, 2026-10-05) already flagged both of these a week
    ago; they are still unresolved. Merging #29 and #30 is lower-risk and faster than waiting
    for next week's report to repeat this finding a third time.
- **`uv` itself (not just a project dependency) has an open Moderate advisory in range:**
  GHSA-2cv4-cqwr-gwf7 (Windows-only path traversal through wheel extraction) affects
  0.12.7–0.12.17 and is fixed in 0.12.18. This repo's pin (0.12.10, identical in three
  places) falls inside that range. Calibrated to this repo: CI is `ubuntu-latest` and the
  Docker image is Linux-only, so the exposure is dev-machine-only and only if a contributor
  works on Windows — real but not CI/production-facing here.
- No CVE/GHSA was found for any other package in this week's outdated list. `cryptography`
  50.0.1 → 50.0.2 is a wheel/OpenSSL-build bump only (no advisory in range; the most recent
  `pyca/cryptography` advisory, CVE-2026-69247, was fixed in 50.0.0, already satisfied by the
  current lock). `cryptography` is the package `reference.md` specifically flags as a
  historically unnoticed-CVE source (a transitive of `fastmcp`, invisible to targeted
  upgrades) — this week's full `uv lock --upgrade` cross-check did catch it, just nothing
  security-relevant in this particular range.

## New community practices

- **PEP 735 `[dependency-groups]` over `[project.optional-dependencies]` for dev tooling** —
  community guides (e.g. the Open edX uv adoption decision record) continue to recommend this
  split. (verified) This repo already does it — no action.
  [Source](https://open-edx-proposals.readthedocs.io/en/latest/best-practices/oep-0067/decisions/backend/0001-uv.html)
- **FastAPI 0.142+ ships a built-in, opt-in OpenTelemetry integration** instead of requiring
  the separate `opentelemetry-instrumentation-fastapi` package. (verified via release notes)
  Not currently used here and not needed unless/until this project adds tracing — flagged for
  awareness only. [Source](https://github.com/fastapi/fastapi/releases)
- **Starlette 1.7 adds an experimental `OpenTelemetryMiddleware`** and exposes the matched
  route via `scope["route"]`. (verified via release notes) Same status as above: awareness
  only, no current use case in this repo. [Source](https://github.com/encode/starlette/releases)
- **mypy 2.4 defaults to the Ruff-based native parser**, and `--num-workers` parallel checking
  is no longer experimental. (verified via `python/mypy` `CHANGELOG.md`) Worth re-timing
  `uv run mypy .` after the lock-step bump above, since this repo runs mypy with several
  strict flags (`disallow_any_generics`, `disallow_untyped_defs`, etc.) that the native
  parser hasn't been exercised against here yet.
  [Source](https://raw.githubusercontent.com/python/mypy/refs/heads/master/CHANGELOG.md)
- **MCP community guidance keeps recommending Streamable HTTP (over SSE) for remote/
  multi-client servers, with Host/Origin validation against DNS rebinding.** (unverified —
  third-party blog sources, not the official MCP spec) This repo already uses Streamable
  HTTP (`mcp.http_app(transport="http", ...)`, per `CLAUDE.md`) and already requires the
  Bearer token on `/mcp` in local mode; the cloud-env auth path is a documented placeholder in
  `src/middleware.py`, unchanged this week — not a new finding, just a pointer to existing
  repo documentation. [Source](https://startdebugging.net/2026/07/mcp-stdio-vs-http-vs-sse-transport-which-to-choose/)

## Recommendations

1. **Merge the two existing Dependabot security PRs now: #29 (`pyjwt`→2.15.0) and #30
   (`virtualenv`→21.7.13).** Both are already open, already green-pathed by Dependabot, have
   been sitting unmerged for 11 days, and were already flagged in last week's report (#31).
   This is strictly lower-effort than re-deriving the fix — no reason to wait for a third
   report to repeat the finding.
2. **Re-run `uv audit` outside this sandbox before trusting "no known CVEs."** This
   environment's egress policy blocks `api.osv.dev`; CI's `check` job already runs the same
   command on every PR, so confirm there rather than treating this report's Security section
   as a clean bill of health. It also won't surface the two findings above, since neither
   `pyjwt` nor `virtualenv` is a direct dependency it tracks the same way Dependabot does.
3. **Bump the `uv` pin in all three locations (Dockerfile, `uv-pre-commit` rev, CI's
   `setup-uv` `version:`) to at least 0.12.18 (0.13.0 recommended)** to close
   GHSA-2cv4-cqwr-gwf7. Low urgency given this repo's Linux-only CI/Docker surface, but it's
   a one-line, risk-free change and keeps the three pins' documented invariant intact.
4. **Bump `fastmcp` to 4.1.0 next**, reading the 4.1.0 breaking-change notes (MultiAuth
   client-ID qualification) first — this repo's MCP mount is a direct consumer of FastMCP's
   HTTP/auth stack, so the accumulated 4.0.6–4.0.11 security fixes apply directly.
5. **Bump `mypy` and the `mirrors-mypy` pre-commit rev together to 2.4.0**, then run
   `make check` — the standing decision requires lock-step movement, and 2.4.0's new default
   parser is worth confirming against this repo's strict mypy config before merging.
6. **Routine bump: `fastapi`, `starlette`, `uvicorn`, `coverage`, `ruff` (+ `ruff-pre-commit`
   rev) and the remaining transitives** via `uv lock --upgrade`, followed by the verification
   ritual (`uv sync --locked` → `make check` → `make cov` → `make smoke`). None of these carry
   a breaking change that applies to this repo's actual configuration.
7. **Bump `docker/build-push-action` to v7.4.0** for its workflow-command-injection fix, and
   `actions/checkout` (major) and `astral-sh/setup-uv` (major, action wrapper) with their
   changelogs reviewed first, plus the minor-only `docker/setup-buildx-action`, `typos`, and
   `shellcheck-py` revs.
