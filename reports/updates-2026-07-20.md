# Weekly Updates Report — 2026-07-20

## Summary

- **Stack is largely up-to-date**: only two packages have available patch upgrades (`fastapi` 0.139.1 → 0.139.2 and `ruff` 0.15.21 → 0.15.22); no security-critical gaps were found.
- **FastMCP 3.4.x had a notable security patch cycle**: 3.4.1 addressed a Starlette CVE (CVE-2026-48710); 3.4.3 introduced a Host/Origin guard that was later relaxed in 3.4.4 (current). The project is already on 3.4.4 — no action needed, but opt-in hardening is available.

- **MCP ecosystem is maturing rapidly** (97 M downloads, 6 400+ registered servers); FastMCP 3.x's new provider/transform architecture and `fastmcp-slim` distribution are worth tracking as the project grows.

## New Community Practices

### FastAPI / Pydantic v2

- **Frontend dependency injection (FastAPI 0.139.0)** — `app.frontend()` now supports `Depends()`-based auth, allowing static assets to be guarded by the same dependency system used for REST routes. Relevant if this project serves a frontend in future.  
  Source: <https://www.skakarh.com/blog/fastapi-0-139-0-released>

- **Pydantic v2 is the performance baseline** — Pydantic v2 (Rust core) delivers 5–50× faster validation than v1. This project already uses pydantic 2.13.4; keep schemas away from `dict[str, Any]` to maximise the benefit.  
  Source: <https://medium.com/@2nick2patel2/fastapi-under-load-in-2026-pydantic-v2-uvloop-http-3-what-actually-moves-the-needle-74717b74e74e>

### FastMCP 3.x Ecosystem

- **`fastmcp-slim`** — a dependency-light distribution (FastMCP 3.3+) that omits the full server framework for client-only consumers. Consider it if a future service only needs the MCP client.  
  Source: <https://github.com/PrefectHQ/fastmcp/releases>

- **`fastmcp-remote`** — a standalone utility (FastMCP 3.4+) that bridges stdio-only MCP hosts to remote Streamable HTTP / SSE servers. Useful if this project needs to expose its MCP endpoint to desktop AI tools.  
  Source: <https://github.com/PrefectHQ/fastmcp/releases>

- **FastMCP 3.4.3 Host/Origin guard** — a CSRF-style defense was introduced and then relaxed in 3.4.4 to opt-in. The guard is available via explicit `trusted_hosts` / `trusted_origins` config for deployments that want it.  
  Source: <https://github.com/PrefectHQ/fastmcp/releases/tag/v3.0.0>

- **Starlette CVE-2026-48710** (addressed in FastMCP 3.4.1) — FastMCP floors Starlette at `>=1.0.1`; the project indirectly benefits because uv resolves Starlette through FastMCP's constraint.  
  Source: <https://data.safetycli.com/packages/pypi/fastmcp/changelog>

### Python Typing

- **Python 3.14 deferred annotations are now the default** — `from __future__ import annotations` is no longer needed in Python 3.14+ files. New files can omit it; existing ones work either way. This project requires `>=3.13`, so the change applies when 3.14 is targeted.  
  Source: <https://typing.python.org/en/latest/guides/modernizing.html>

- **Modern generic syntax (Python 3.12+)** — `def first[T](items: list[T]) -> T` is now preferred over `TypeVar`-based generics. The CLAUDE.md standards already mandate `list`, `dict`, `str | None` — extend this to generic type parameters when they appear.  
  Source: <https://typing.python.org/en/latest/guides/modernizing.html>

### MCP Ecosystem

- **MCP hit 97 M downloads and 6 400+ registered servers by mid-2026** — it is now adopted by OpenAI, Google DeepMind, and Microsoft, making it a stable integration target.  
  Source: <https://www.sitepoint.com/model-context-protocol-mcp/>

- **MCP security posture** — the community recommendation is to treat all MCP tool inputs as untrusted and apply strict Pydantic schemas. FastAPI + FastMCP already enforce this via route-level validation, but it is worth reviewing any future tools that accept free-form strings.  
  Source: <https://lushbinary.com/blog/mcp-model-context-protocol-developer-guide-2026/>

### uv Workflows

- **uv is the go-to Python package manager in 2026** — the recommended baseline workflow (`uv run`, `uv add`, committed `uv.lock`) is already in use here. No changes needed.  
  Source: <https://dev.to/moksh/why-uv-became-the-go-to-python-package-manager-in-2026-2kag>
