# Weekly Updates Report — 2026-09-07

## Summary

- **FastMCP 4.0.3 is a major release** built on the new stateless 2026-07-28 MCP protocol spec; the project currently pins `>=3.4.4` and will not receive 4.x automatically — an upgrade plan is needed.
- **Ruff 0.16** expanded its default rule set from 59 to 413 rules; upgrading will likely surface new lint failures that require fixes or explicit suppressions in `ruff.toml`.
- **mypy is pinned** at `==2.3.0` while `2.3.1` (patch) is already available — the strict pin blocks automatic patch uptake.
- Most other dependencies (fastapi, uvicorn, pydantic-settings, coverage, pre-commit) have routine minor/patch updates with no breaking changes.
- The MCP ecosystem has broadly adopted `ToolAnnotations` and a registry-first approach in 2026; both are worth incorporating as the project matures.

## New Community Practices

- **MCP 2026-07-28 stateless protocol** — The July 2026 MCP spec revision replaced the persistent-session model with a stateless one. FastMCP 4.0 is built on this; FastMCP 3.x implements the legacy 2025-11-25 protocol. Projects using `FastMCP.from_fastapi()` should audit for session-scoped assumptions. Source: [Beta SDKs for the 2026-07-28 MCP Spec](https://blog.modelcontextprotocol.io/posts/sdk-betas-2026-07-28/)

- **ToolAnnotations for every MCP tool** — The March 2025 MCP spec introduced `ToolAnnotations` (safety, idempotency, side-effect hints). These are now expected by major AI hosts and registries; unannotated tools may receive lower trust rankings in registries. Source: [MCP Ecosystem 2026](https://www.mcp-conference.com/resources/mcp-ecosystem-2026)

- **Ruff 0.16 zero-config linting** — With 413 rules enabled by default, Ruff increasingly replaces manual `ruff.toml` rule selection. The community pattern is now: enable defaults, selectively disable with `ignore = [...]` for project-specific carve-outs, and drop legacy per-rule enables. Source: [Ruff v0.16.0 — Astral](https://astral.sh/blog/ruff-v0.16.0)

- **uv as the standard Python toolchain** — `uv run` / `uv add` / `uv sync` is the dominant 2026 workflow for FastAPI projects. The `uvx` shorthand (`uvx ruff check`) is preferred over `uv run ruff` in one-off tooling invocations. Docker images using uv's multi-stage pattern are significantly smaller. Source: [uv + Ruff fastest workflow 2026](https://www.pyinns.com/python/efficient-code/uv-ruff-fastest-python-workflow-2026)

- **Pydantic `Annotated` reusable types** — The current idiomatic pattern is `type EmailStr = Annotated[str, Field(...)]` (Python 3.12+ `type` statement) for reusable validated types across models — cleaner than repeating `Annotated[...]` inline. The `CLAUDE.md` already discourages `Any`; this practice reinforces it. Source: [Working with Pydantic v2 best practices](https://medium.com/algomart/working-with-pydantic-v2-the-best-practices-i-wish-i-had-known-earlier-83da3aa4d17a)

- **FastAPI `app.frontend()` and background task improvements** — FastAPI 0.141.x fixed background-task and header propagation through dependencies in `app.frontend()`; worth noting if this project adds UI routes. Source: [FastAPI release notes](https://fastapi.tiangolo.com/release-notes/)

## Recommendations

Ordered by priority:

1. **(HIGH) Plan FastMCP 4.0 upgrade** — FastMCP 4.0.3 is a major release on a new protocol spec. Test locally with `uv add fastmcp>=4.0.0`; most FastMCP 3 apps upgrade without code changes per the release notes, but verify the `FastMCP.from_fastapi()` mounting and the MCP lifespan wiring in `src/main.py`. Update the constraint to `>=4.0.3` only after confirming behaviour in tests.

2. **(HIGH) Audit Ruff 0.16 new defaults** — Run `uv add --dev ruff>=0.16.6` then `uv run ruff check .`. Expect new findings from the 413-rule default set. Fix genuine issues; add explicit `ignore` entries in `ruff.toml` for rules that do not apply. The new `ruff: ignore` inline comment syntax is a useful alternative to `# noqa`.

3. **(MEDIUM) Unpin mypy** — Change `mypy==2.3.0` → `mypy>=2.3.1` (or `>=2.3.0`) in `pyproject.toml` to receive patch releases automatically. Patch bumps in mypy are low-risk.

4. **(MEDIUM) Bump minor/patch deps** — Raise lower bounds for `fastapi>=0.141.1`, `uvicorn>=0.52.4`, `pydantic-settings>=2.15.0`, `coverage>=7.16.0`, `pre-commit>=4.6.2`. These are all backwards-compatible; running `uv lock --upgrade-package <name>` and re-running the test suite is sufficient validation.

5. **(LOW) Add `ToolAnnotations` to MCP tools** — As the project exposes tools via `FastMCP.from_fastapi()`, annotate each route with `ToolAnnotations` (e.g., `readOnlyHint`, `idempotentHint`) once upgraded to a spec-compliant FastMCP. This is a no-op in FastMCP 3 but will be picked up automatically in FastMCP 4.

6. **(LOW) Consider a `uvx` alias in `Makefile`** — Replace `uv run ruff check .` with `uvx ruff check .` in the Makefile targets to align with the 2026 community convention for one-shot tooling.
