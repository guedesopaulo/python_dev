# Weekly Updates Report — 2026-08-03

## Summary

- **Ruff 0.16.x** (pinned at 0.15.21) is the most impactful dev-tooling upgrade: it expands default lint rules from 59 to 413, which will break CI if applied without careful configuration review.
- **FastMCP v4.0.0b1** landed on 2026-07-28 alongside the MCP Python SDK v2, introducing a breaking protocol migration from stateful/bidirectional to stateless/sessionless. Active planning for migration is needed, as `FastMCP.from_fastapi()` semantics will change.
- **FastAPI** is two minor versions behind (0.139.1 → 0.141.1); the upgrade is non-breaking and adds OpenAPI 3.1.0 support, webhooks documentation, and Swagger UI 5.x.
- **uvicorn 0.51.0 → 0.52.1** ships an experimental HTTP/1.1 implementation backed by `zttp` (fuzzer-hardened, security-audited); minor version, low risk.
- All other dependencies are at current versions or have only patch-level gaps (coverage, pre-commit).

## New Community Practices

- **Ruff 0.16 default rule expansion** — The linter now enables 413 rules by default (up from 59), adding flake8-bugbear (B), pyupgrade (UP), Pylint (PL), and flake8-simplify (SIM) categories. Several previously-default pycodestyle/pyflakes rules were removed. Pipelines with unpinned or loose ruff versions broke across the ecosystem on release day (2026-07-23). Recommended workflow: run `ruff check .` under the new version in a branch to assess the delta before committing to the upgrade.
  Source: [Ruff v0.16.0 — Astral](https://astral.sh/blog/ruff-v0.16.0)

- **MCP Python SDK v2 / FastMCP v4 — Sessionless protocol** — The MCP spec revision 2026-07-28 moves the protocol from stateful bidirectional connections to stateless request/response. FastMCP v4 adapts the abstraction layer so tools can still express multi-round state, but the underlying transport is sessionless. The low-level `Server` interface changed: handlers are now constructor parameters instead of decorators; return values are no longer auto-wrapped; field names are `snake_case`.
  Source: [MCP Python SDK v2 — What's New](https://py.sdk.modelcontextprotocol.io/whats-new/) · [FastMCP Changelog](https://gofastmcp.com/changelog) · [Medium: MCP migrating v1 → v2](https://medium.com/the-ai-language/mcp-is-migrating-from-version-1-to-version-2-07f4cc7624fb)

- **FastAPI 0.141 — OpenAPI 3.1 and Swagger UI 5.x** — The `0.141` line upgraded the bundled Swagger UI to v5.x (required for OpenAPI 3.1 rendering) and added first-class support for documenting webhooks via `@app.webhooks`. No breaking changes to existing routes.
  Source: [FastAPI 0.141 updates — Releasebot](https://releasebot.io/updates/tiangolo/fastapi)

- **Pydantic v2: `TypeAdapter` and `exclude_unset`** — Current community guidance emphasises using `TypeAdapter` for validating standalone types (e.g. `list[int]`) without defining a full `BaseModel`, and `model.model_dump(exclude_unset=True)` for PATCH endpoint payloads to avoid inadvertently overwriting fields the caller did not provide.
  Source: [Pydantic v2 Core Tutorial — Medium](https://medium.com/engineering-playbook/pydantic-v2-core-tutorial-models-fields-validators-dc2cd85b17dc)

- **uv: always commit `uv.lock`** — The `uv.lock` file should be committed to the repository so all contributors and CI reproduce identical environments via `uv sync`. Use `uv run` instead of activating the virtualenv manually; use `uv add` to add packages (it updates both `pyproject.toml` and `uv.lock` atomically).
  Source: [uv Python Package Manager Guide 2026 — ToolsMint](https://www.toolsmint.com/learn/uv-python-package-manager-guide-2026)

- **uvicorn 0.52 — experimental HTTP/1.1 via `zttp`** — The new `zttp`-backed HTTP/1.1 parser is opt-in in 0.52; it has been fuzz-tested and security-audited and is expected to become the default in a future release. Enabling it early is low-risk in non-production environments.
  Source: [Release Notes — Uvicorn](https://uvicorn.dev/release-notes/)

## Recommendations

### Priority 1 — Plan FastMCP v4 migration (urgent, breaking)

FastMCP 4.0.0b1 (2026-07-27) and MCP Python SDK v2 are available in beta. The project's `main.py` uses `FastMCP.from_fastapi(app)` and mounts the result at `/mcp`. The stable v4 release is imminent; review the FastMCP v3 → v4 migration guide before it ships. At minimum, pin `fastmcp<4` now (e.g. `fastmcp>=3.4.4,<4`) to prevent an accidental breaking upgrade via `uv update`.

### Priority 2 — Upgrade Ruff carefully (important, may surface real issues)

Before upgrading from 0.15.21 to 0.16.x, run `uv run ruff check . --select ALL` locally to preview the new default rule output. Then update the `ruff.toml` with explicit `ignore` entries for rules you intentionally want to skip (the project already ignores UP040). The 413-rule default will likely catch real modernisation opportunities (type-hint upgrades, mutable defaults). Do not `uv update ruff` without this dry run — CI breakage is near-certain without it.

### Priority 3 — Upgrade FastAPI to 0.141.1 (low risk, worthwhile)

`uv add "fastapi>=0.141.0"` and run the test suite. OpenAPI 3.1 and Swagger UI 5.x are additive; no endpoint or Pydantic model changes should be required.

### Priority 4 — Upgrade uvicorn to 0.52.1 (low risk)

`uv add "uvicorn>=0.52.1"`. Consider testing the `zttp` HTTP/1.1 backend on a development branch (pass `--http zttp` to uvicorn) to provide early feedback before it becomes the default.

### Priority 5 — Patch upgrades for coverage and pre-commit (routine)

Run `uv lock --upgrade-package coverage --upgrade-package pre-commit` to pick up 7.15.3 and 4.6.1 respectively. These are minor bug-fix releases with no configuration changes required.

### Priority 6 — Review `PATCH` endpoint patterns with Pydantic v2

When PATCH endpoints are added to this codebase (following the layered module pattern), use `model.model_dump(exclude_unset=True)` rather than serializing the full model, to avoid resetting fields the caller did not supply.
